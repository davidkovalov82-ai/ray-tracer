# Форматирование, сборка и вызовы системы

## 1. Настройки стиля (.clang-format)

**Вопрос:** Почему мы написали `BasedOnStyle: Google`, `IndentWidth: 4` и другие странные слова в `.clang-format`?

**Смысл:** `.clang-format` — это конфигурационный файл для программы `clang-format`, которая автоматически делает ваш код красивым и читаемым. Без него программисты постоянно бы спорили, сколько пробелов ставить.

**Как работает:**
- `BasedOnStyle: Google` — берет за основу готовый свод строгих правил от компании Google.
- `IndentWidth: 4` — переопределяет правило Google (у них 2 пробела) на 4 пробела для отступов.
- `UseTab: Never` — запрещает использовать символ `Tab` (табуляцию). Везде будут ставиться только пробелы. Это нужно, чтобы код выглядел одинаково в любом редакторе (у кого-то Tab это 2 пробела, у кого-то 8).
- `ColumnLimit: 100` — разрешает писать до 100 символов в одной строке (вместо стандартных 80). Если строка длиннее, она автоматически перенесется.
- `AccessModifierOffset: -4` — указывает, как выравнивать слова `public:` и `private:` в классах (они сдвигаются влево на 4 пробела относительно остального кода).

**Вывод:** Файл гарантирует, что редактор отформатирует код именно так, как вы задумали, независимо от того, кто открыл проект.

## 2. Makefile и его команды

**Вопрос:** Почему мы пишем `.PHONY: all build run test clean` и что значит `all: build run test`?

**Смысл:** `Makefile` — это файл-шпаргалка для программы `make`, которая автоматизирует запуск длинных консольных команд.

**Как работает:**
Каждый блок в `Makefile` — это "цель" (команда) и инструкции для неё.
Например:
```makefile
test:
	python3 test/test.py
```
Когда вы пишете `make test`, программа `make` находит цель `test` и выполняет всё, что под ней написано (с отступом `Tab`).

- `all: build run test` — это составная цель. Она говорит: "Чтобы выполнить `all`, сначала выполни цель `build`, потом `run`, потом `test`". Это позволяет запустить весь цикл одной короткой командой `make all` (или просто `make`, так как `all` идет первой).
- `.PHONY: ...` — сообщает `make`, что `all`, `build`, `run` — это *имена команд*, а не имена файлов на диске. Если бы у вас случайно лежал файл с именем `test`, без `.PHONY` программа `make` могла бы запутаться и сказать: "Файл test уже есть, мне не нужно ничего делать".

**Вывод:** `Makefile` экономит время, превращая длинные команды в короткие псевдонимы.

## 3. Взаимодействие с системой (std::system)

**Вопрос:** Как работает `std::system(...)` и что за магия `> /dev/null 2>&1`?

**Смысл:** `std::system` позволяет вашей программе на C++ "напечатать" команду в терминал так, будто это сделали вы сами руками.

**Как работает:**
```cpp
int status = std::system("sips -s format png images/ppm/image.ppm --out images/png/image.png > /dev/null 2>&1");
```
Функция берет строку и передает её операционной системе (macOS). macOS запускает встроенную утилиту `sips` для конвертации картинки.
Функция возвращает `int` (число). По правилам ОС: `0` значит успех, любое другое число — ошибка. Поэтому мы делаем проверку `if (status == 0)`.

**Что такое `> /dev/null 2>&1`:**
Утилита `sips` при успешной работе выводит много текста в консоль (пути к файлам, размеры). Чтобы этот системный текст не смешивался с красивым выводом нашей программы:
- `> /dev/null` — перенаправляет обычный вывод команды в "черную дыру" (он нигде не отобразится).
- `2>&1` — берет сообщения об ошибках (поток номер 2) и отправляет их туда же, куда и обычный вывод (поток 1), то есть тоже в "черную дыру".

**Вывод:** Вы можете запускать любые консольные команды прямо из C++, но не забывайте проверять, успешно ли они выполнились.
