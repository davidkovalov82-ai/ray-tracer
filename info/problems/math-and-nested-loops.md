# Математика и циклы: Расширенный разбор

## 1. Вложенные циклы и почему `j` потом `i`

**Смысл:** Изображение — это сетка 2D. Нам нужно заполнить её построчно.

В нашем проекте мы используем классический двойной цикл:

```cpp
// Классический подход (2D сетка)
for (int j = 0; j < image_height; ++j) {
    for (int i = 0; i < image_width; ++i) {
        // Мы четко знаем, что сейчас находимся на строке j и в колонке i.
        // Вычисляем цвет для пикселя (i, j)...
    }
}
```

**Как это работает:**
Внешний цикл (`j`) "держит" текущую строку. Пока он стоит на `j = 0`, внутренний цикл (`i`) пробегает все значения от `0` до `255`. Это заполняет одну горизонтальную линию. Затем `j` становится `1`, и мы заполняем следующую линию.

### Альтернативный подход (Расширение кругозора): Цикл 1D
Знаете ли вы, что любую двумерную сетку пикселей можно обойти с помощью *одного* цикла? Так как все пиксели лежат в векторе друг за другом в один ряд, мы можем посчитать их общее количество и использовать деление с остатком (`%`), чтобы математически вычислить текущую колонку и строку:

```cpp
int total_pixels = image_width * image_height;

for (int k = 0; k < total_pixels; ++k) {
    int j = k / image_width; // Строка: целочисленное деление (например, 257 / 256 = 1)
    int i = k % image_width; // Колонка: остаток от деления (например, 257 % 256 = 1)
    
    // ... вычисляем цвет для (i, j)
}
```
*Почему мы не используем 1D подход в Ray Tracer?*
Хотя 1D цикл выглядит лаконичнее (один `for` вместо двух), классический двойной `for` читается гораздо понятнее для человека. Нам постоянно нужны координаты `(x, y)` или `(i, j)` для генерации лучей в 3D пространстве. Вычислять их делением на каждом шаге — это лишняя математика для процессора. Поэтому классические вложенные циклы — абсолютный стандарт для работы с изображениями.

## 2. Инкремент: почему `++i` лучше, чем `i++`

В программировании на C++ есть два способа увеличить число на единицу:
1. Постфиксный: `i++`
2. Префиксный: `++i`

**Давайте посмотрим на фрагмент кода, показывающий реальную разницу:**
```cpp
int a = 5;
int b = a++; // Постфиксный: сначала 'b' получает 5, и только ПОТОМ 'a' становится 6.
// Итог: a = 6, b = 5

int x = 5;
int y = ++x; // Префиксный: сначала 'x' становится 6, и СРАЗУ ЖЕ 'y' получает 6.
// Итог: x = 6, y = 6
```

**Почему в циклах принято писать `++i`?**
Если переменная `i` — это сложный объект (например, итератор из предыдущего урока), постфиксный инкремент `i++` вынужден "под капотом" создавать временную копию старого значения в оперативной памяти, чтобы вернуть её до увеличения. 
Префиксный `++i` увеличивает значение сразу на месте и не создает мусорных копий. 

Для простых чисел типа `int` современные компиляторы автоматически сглаживают эту разницу и ускоряют код. Но привычка писать `++i` в `for` — это "золотое правило" и негласный стандарт качественного кода в C++.

## 3. Математика нормализации (Деление на `N - 1`)

Нам нужно перевести координаты пикселя `[0, 255]` в дробный диапазон процентов `[0.0, 1.0]`, где `0.0` — это 0%, а `1.0` — 100% интенсивности цвета.

```cpp
// Наш код
double r = double(i) / (image_width - 1);
```

**Зачем `- 1`? Разбор на простом примере**
Представьте, что ширина картинки всего 3 пикселя (`image_width = 3`). 
Координата `i` будет принимать значения `0, 1, 2`. Сначала мы пишем `double(i)`, чтобы превратить целое число в дробное (иначе C++ выполнит целочисленное деление с отбрасыванием остатка: `1 / 3` станет просто `0`).

*Вариант А: Делим просто на ширину (`3.0`)*
- `i = 0`: `0.0 / 3.0 = 0.0` (черный)
- `i = 1`: `1.0 / 3.0 = 0.33` (темно-красный)
- `i = 2`: `2.0 / 3.0 = 0.66` (светло-красный, но не 100%!)
Итог: Мы никогда не достигнем цвета `1.0` (чистого). Правый край картинки будет тусклым.

*Вариант Б: Делим на `(ширина - 1)`, то есть на `2.0`*
- `i = 0`: `0.0 / 2.0 = 0.0` (черный)
- `i = 1`: `1.0 / 2.0 = 0.5` (средний)
- `i = 2`: `2.0 / 2.0 = 1.0` (чистый 100% красный!)
Итог: Градиент плавно и идеально растягивается от края до края.

Эта математическая концепция называется **линейной интерполяцией**. В новом стандарте C++20 даже появилась специальная библиотечная функция `std::lerp(a, b, t)`, которая берет на себя подобные вычисления, плавно находя промежуточное значение между `a` и `b` на основе процента `t`. В нашем случае (в C++17) мы делаем эту базовую математику вручную.
