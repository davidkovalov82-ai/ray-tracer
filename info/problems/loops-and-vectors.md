# Векторы, коллекции и касты: Расширенный разбор

## 1. Возможности `std::vector` (Не только `push_back`)

`std::vector` — это один из самых мощных инструментов в стандартной библиотеке C++ (`<vector>`). В нашем коде мы использовали `reserve` и `push_back`, но давайте расширим кругозор и посмотрим, как ещё можно было решить нашу задачу.

### Наш текущий способ (Reserve + Push_back)
```cpp
std::vector<Color> pixels;
// Резервируем память (capacity), но реальный размер (size) вектора = 0
pixels.reserve(width * height); 

for (int j = 0; j < height; ++j) {
    for (int i = 0; i < width; ++i) {
        // Добавляем в конец, размер вектора растет на 1 с каждым шагом
        pixels.push_back(Color{r, g, b}); 
    }
}
```

### Альтернативный способ (Resize + Индексы)
Мы могли бы сразу задать реальный размер вектору и потом просто менять уже готовые элементы, обращаясь к ним как в классическом массиве `[]`:

```cpp
std::vector<Color> pixels;
// Resize физически создает width * height пустых (черных) пикселей.
// size() теперь равен 65536.
pixels.resize(width * height); 

for (int j = 0; j < height; ++j) {
    for (int i = 0; i < width; ++i) {
        // Вычисляем индекс в одномерном массиве (формула: строка * ширина + колонка)
        int index = j * width + i; 
        
        // Перезаписываем существующий цвет
        pixels[index] = Color{r, g, b}; 
    }
}
```
*Что лучше?* `reserve` + `push_back` чуть безопаснее для простых задач — вы не можете промахнуться мимо индекса. Но `resize` + индексы используется в графике, когда пиксели нужно изменять хаотично или читать из вектора старые значения перед записью новых.

### Полезные методы `std::vector`, которые вам точно пригодятся:
- `pixels.size()` — возвращает текущее количество элементов.
- `pixels.capacity()` — возвращает размер *зарезервированной* памяти (всегда больше или равно `size()`).
- `pixels.empty()` — вернет `true`, если вектор пуст (работает быстрее и читается лучше, чем `if (pixels.size() == 0)`).
- `pixels.clear()` — удаляет все элементы (размер становится `0`), но **оставляет память зарезервированной** (capacity остается старым), чтобы в будущем можно было снова быстро заполнить вектор.

## 2. Эволюция циклов в C++

В функции сохранения `save_ppm` мы использовали Range-based for цикл: `for (const auto& pixel : pixels)`. Давайте посмотрим, как развивался язык C++ и какие у нас были альтернативы для обхода вектора.

### Способ 1: Классика из языка C (По индексам)
Работает всегда, но требует много писанины. Удобно, если внутри цикла нужно знать текущий номер (индекс) элемента.
```cpp
for (size_t i = 0; i < pixels.size(); ++i) {
    // Нам приходится каждый раз обращаться к вектору по индексу
    Color pixel = pixels[i]; 
    out << int(pixel.r * 255) << " ...\n";
}
```

### Способ 2: Итераторы (Стиль старых стандартов C++98 / C++03)
До появления современного цикла программисты использовали "итераторы" — специальные объекты-курсоры, которые умеют ходить по коллекциям.
```cpp
// it - это "курсор", который указывает на элемент
for (std::vector<Color>::const_iterator it = pixels.begin(); it != pixels.end(); ++it) {
    // Чтобы получить сам пиксель из итератора, ставим звездочку (разыменовываем)
    Color pixel = *it; 
    out << int(pixel.r * 255) << " ...\n";
}
```
*Минус:* Код выглядит ужасно громоздко и его тяжело читать.

### Способ 3: Range-based for (Современный C++11 и выше)
Скрывает под капотом всю тяжелую работу с итераторами.
```cpp
for (const auto& pixel : pixels) {
    out << int(pixel.r * 255) << " ...\n";
}
```
**Резюме:** Всегда используйте 3-й способ, если вам нужно просто перебрать все элементы вектора от начала до конца.

## 3. Приведение типов: `static_cast` vs `(int)`

Для перевода дробного числа в целое (для PPM) мы написали:
```cpp
int ir = static_cast<int>(pixel.r * 255.0);
```

**Альтернатива: С-style cast (Старый стиль языка C)**
```cpp
int ir = (int)(pixel.r * 255.0);
```

**Почему `static_cast` лучше?**
Круглые скобки `(int)` — это "грубое приведение" (brute force cast). Если компилятор может привести тип — он это сделает, даже если это плохая идея (например, случайно превратит адрес в памяти в число). Ошибку вы получите только во время работы программы (программа упадет).

`static_cast<...>` — это строгий и безопасный инструмент C++. Он проверяет легальность математической операции *до* компиляции. Плюс, слово `static_cast` легко найти поиском по проекту (Ctrl+F), чтобы проверить, где именно программист искусственно меняет типы данных.

**Для кругозора — другие виды кастов в C++:**
- `dynamic_cast` — безопасно переводит один объект в другой по иерархии (используется в ООП и наследовании классов).
- `reinterpret_cast` — "хакерский" каст: говорит компилятору "забудь о типах, просто смотри на эти нули и единицы в памяти как на совсем другой объект".
- `const_cast` — снимает запрет `const` с переменной (опасен, используется только когда старая библиотека требует неконстантную переменную, а вы гарантируете, что она не изменится).
